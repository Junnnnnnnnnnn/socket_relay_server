CONTROLLER

Climb Socket API – Controller 문서

연결 안 됨

개요

Climb Controller는 플레이어가 흔들어(shake) 올라가는 단말입니다. 서버의 climb 네임스페이스에 role=controller로 접속하여 EMIT 으로 입력을 보내고, LISTEN 으로 방 상태·진행도·게임 종료를 받습니다.

연결 정보

URL:       https://socket-relay.zipshowkorea.com/climb
Transport: WebSocket / Polling (auto)
Library:   socket.io-client@4.x
Query:     ?room=<방 코드>          (필수)
           &role=controller           (기본값)
중요: 방은 Display가 먼저 role=display로 접속하여 만들어야 합니다. Controller만 접속하면 임시 방이 만들어지지만 startGame에서 NO_DISPLAY 오류가 발생합니다.

기본 사용 예시

import io from 'socket.io-client';

const socket = io('https://socket-relay.zipshowkorea.com/climb', {
  query: { room: 'room-1', role: 'controller' },
});

socket.on('connect', () => {
  socket.emit('joinRoom', { room: 'room-1', name: 'Junn' });
});

socket.on('joinedRoom', (d) => console.log('joined', d));
socket.on('gameStarted', () => startShakeLoop());
socket.on('stateUpdate', (d) => renderProgress(d.players));
socket.on('gameOver', (d) => showResult(d));

EMIT Controller → Server

컨트롤러가 서버로 보내는 이벤트. 버튼을 눌러 실제 서버로 전송해볼 수 있습니다.

EMITjoinRoom

방에 실제 플레이어로 등록. 최대 4명. 방 없으면 error(NO_SUCH_ROOM), 꽉 차면 별도 roomFull 이벤트.
이미 같은 방에 들어와 있는 본인의 재-joinRoom(이름 변경/재연결 등)은 정원 체크에서 제외되어 정상 처리됩니다.

// payload
{ room: string, name?: string }   // name 없으면 P1/P2/... 자동 부여

socket.emit('joinRoom', { room: 'room-1', name: 'Junn' });
실시간 서버로 전송
EMITstartGame

게임 시작. 2명 이상이어야 하고 Display가 방에 있어야 함. 그렇지 않으면 NOT_ENOUGH_PLAYERS / NO_DISPLAY 오류.

socket.emit('startGame');   // no payload
EMITshake

흔들림 샘플. 서버가 delta를 0~20으로 clamp 후 gain=0.01로 스케일해 progress(%)에 누적. 100%에 도달하면 gameOver.

// payload
{ delta: number }   // 0..20 (서버에서 clamp)

socket.emit('shake', { delta: 15 });
내 progress 0% idle
꾹 누르는 동안 { delta: 15 }를 100ms 간격으로 전송.
EMITjoin-queue

대기열에 자신의 소켓 ID 추가. 서버는 전역으로 status-queue 브로드캐스트.

socket.emit('join-queue');   // no payload
EMITleave-queue

대기열에서 나간다.

socket.emit('leave-queue');  // no payload
EMITstatus-queue

큐 스냅샷을 요청자에게만 반환.

socket.emit('status-queue');
socket.on('status-queue', (queue) => console.log(queue));
EMITgameOver

게임을 수동으로 종료. 서버는 방 상태를 'ended'로 바꾸고 같은 룸의 모든 클라이언트에게 gameOver를 브로드캐스트한 뒤, 해당 룸의 모든 소켓을 강제 disconnect 합니다(자동 정리). winnerId·reason은 옵셔널이며 미지정 시 각각 null, 'manual'로 채워집니다.

// payload (둘 다 옵셔널)
{ winnerId?: string | null, reason?: string }

socket.emit('gameOver', { winnerId: socket.id, reason: 'reached_top' });
// 또는
socket.emit('gameOver');
룸 전체에 gameOver 브로드캐스트
EMITdisconnect-room

해당 방의 모든 소켓(컨트롤러 + 디스플레이)을 강제 연결 해제. 게임 종료 후 방 정리용으로 호출. 룸 이름은 빈 문자열 불가, 최대 64자.

// payload
{ room: string }

socket.emit('disconnect-room', { room: 'room-1' });
실서버 영향 있음 — 방의 모든 소켓이 끊깁니다

LISTEN Server → Controller

아래 이벤트는 서버에서 자동으로 들어옵니다. 오른쪽 로그에서 실시간 확인.

LISTENerror

서버 측 오류. 코드별로 분기 처리하세요.

{ code: string, message: string }

// code 종류:
// - NO_ROOM            연결 시 room 쿼리 누락 (직후 disconnect)
// - NO_SUCH_ROOM       joinRoom 시 방 없음
// - NOT_ENOUGH_PLAYERS startGame 시 플레이어 <2
// - NO_DISPLAY         startGame 시 Display 미접속
LISTENroomFull

방 정원(4명) 초과 시 해당 클라이언트에게만 발행. 참가 실패.

{ room: string, maxPlayers: number }
LISTENjoinedRoom

참가자 입장/퇴장 시 방 전체에 발행. 참가자 리스트 포함.

{
  room: string,
  playerCount: number,
  players: Array<{ socketId: string, name: string }>
}
LISTENroomPlayerCount

인원 수만 경량으로 받을 때. 연결 직후/입퇴장 시 발행.

{ room: string, playerCount: number }
LISTENgameStarted

게임 시작 알림. Controller는 이때부터 shake 입력을 전송.

// no payload
LISTENstateUpdate

참가/퇴장·shake·startGame 등 방 상태가 바뀔 때마다 발행. 본인 + 다른 플레이어 progress 렌더링용.

{
  status: 'idle' | 'running' | 'ended',
  players: Array<{ id: string, name?: string, progress: number }>  // progress 0..100
}
LISTENgameOver

승자 결정 또는 Display 이탈 시 방 전체에 발행.

{
  winnerId: string | null,   // null이면 비정상 종료
  snapshot: { status, players },
  reason?: 'display_disconnected'
}
LISTENstatus-queue

큐 변경 시 모든 클라이언트 브로드캐스트. 요청 응답에도 사용.

string[]   // socketId 배열
