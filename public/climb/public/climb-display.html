DISPLAY

Climb Socket API – Display 문서

연결 안 됨

개요

Climb Display는 게임 화면입니다. 방을 처음 생성하는 주체이며, 참가자 진행도(progress) 막대 렌더링과 승자 배너 표시가 주요 역할입니다. Display가 끊기면 서버는 gameOver(reason: 'display_disconnected')를 발행하고 방을 제거합니다.

연결 정보

URL:       https://socket-relay.zipshowkorea.com/climb
Transport: WebSocket / Polling (auto)
Library:   socket.io-client@4.x
Query:     ?room=<방 코드>   (필수)
           &role=display      (필수 — Controller와 구분)
중요: 방은 연결 시점에 자동 생성됩니다. 이미 방이 존재하면 해당 방의 displayId가 현재 Display로 갱신됩니다. Display는 한 방에 하나만 존재해야 합니다.

기본 사용 예시

import io from 'socket.io-client';

const socket = io('https://socket-relay.zipshowkorea.com/climb', {
  query: { room: 'room-1', role: 'display' },
});

socket.on('joinedRoom',  (d) => renderPlayers(d.players));
socket.on('gameStarted', () => showCountdown());
socket.on('stateUpdate', (d) => renderProgress(d.players));
socket.on('gameOver',    (d) => showWinner(d.winnerId, d.snapshot));

LISTEN Server → Display

Display의 핵심. 아래 이벤트가 들어오는 즉시 오른쪽 패널에 반영됩니다.

LISTENerror

서버 측 오류. Display는 보통 NO_ROOM만 수신합니다 (쿼리 누락 시 → 즉시 disconnect). 정원 초과는 별도 roomFull 이벤트로 분리됨(아래 참고).

{ code: string, message: string }

// code 종류:
// - NO_ROOM            연결 시 room 쿼리 누락 (직후 disconnect)
// - NO_SUCH_ROOM       joinRoom 시 방 없음
// - NOT_ENOUGH_PLAYERS startGame 시 플레이어 부족
// - NO_DISPLAY         startGame 시 Display 미접속
LISTENroomFull

방 정원(최대 4명) 초과 시 해당 클라이언트에게만 발행. Display는 보통 joinRoom을 호출하지 않으므로 직접 받지 않지만, 같은 namespace에서 동작하는 컨트롤러 디버깅 시 참고용.

{ room: string, maxPlayers: number }   // maxPlayers = 4
LISTENjoinedRoom

참가자 입장/퇴장 시 방 전체에 발행. 플레이어 네임태그·슬롯 렌더링용.

{
  room: string,
  playerCount: number,
  players: Array<{ socketId: string, name: string }>
}
LISTENroomPlayerCount

인원 수만 경량으로. Display가 연결되면 먼저 이 이벤트가 발행됨.

{ room: string, playerCount: number }
LISTENgameStarted

Controller의 startGame 요청 성공 시 방 전체에 발행. 카운트다운·배경 전환에 사용.

// no payload
LISTENstateUpdate

방 상태 변경 시마다 발행. 각 플레이어 progress(0~100) 막대 업데이트의 트리거.

{
  status: 'idle' | 'running' | 'ended',
  players: Array<{ id: string, name?: string, progress: number }>
}
LISTENgameOver

100% 도달자가 나오거나 Display가 끊어졌을 때. 우승자 화면 렌더링용.

{
  winnerId: string | null,
  snapshot: {
    status: 'idle' | 'running' | 'ended',
    players: Array<{ id, name?, progress }>
  },
  reason?: 'display_disconnected'
}
LISTENstatus-queue

대기열 변경 시 모든 클라이언트에 발행. 대기 순번 표시에 사용.

string[]   // socketId 배열

EMIT Display → Server

Display가 세션을 관리하기 위해 보내는 이벤트. 실제 서버로 발행해볼 수 있습니다.

EMITreset-queue

대기열 초기화. 서버는 project 룸으로 reset-queue를 브로드캐스트.

// payload
{ project: string }

socket.emit('reset-queue', { project: 'climb' });
EMITstatus-queue

현재 대기열 스냅샷을 요청. 응답은 요청자에게만 전달.

socket.emit('status-queue');
socket.on('status-queue', (queue) => renderQueue(queue));
EMITgameOver

게임을 수동으로 종료. 서버는 방 상태를 'ended'로 바꾸고 같은 룸의 모든 클라이언트에게 gameOver를 브로드캐스트한 뒤, 해당 룸의 모든 소켓을 강제 disconnect 합니다(자동 정리). winnerId·reason은 옵셔널이며 미지정 시 각각 null, 'manual'로 채워집니다.

// payload (둘 다 옵셔널)
{ winnerId?: string | null, reason?: string }

socket.emit('gameOver', { winnerId: 'abc123', reason: 'reached_top' });
// 또는
socket.emit('gameOver');
룸 전체에 gameOver 브로드캐스트
EMITdisconnect-room

해당 방의 모든 소켓(컨트롤러 + 디스플레이)을 강제 연결 해제. 게임 종료 후 방 정리용으로 호출. 룸 이름은 빈 문자열 불가, 최대 64자.

// payload
{ room: string }

socket.emit('disconnect-room', { room: 'room-1' });
실서버 영향 있음 — 방의 모든 소켓이 끊깁니다
Display 소켓이 끊어지면 서버가 자동으로 gameOver (reason: 'display_disconnected') 브로드캐스트 + 방 제거를 수행합니다. 명시적으로 방의 모든 소켓을 한 번에 끊으려면 위 disconnect-room을 사용하세요.
